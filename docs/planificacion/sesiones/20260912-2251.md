# Sesión 2026-09-12 22:51 — La prueba del BOM contra modelos reales

- **Qué cambió**: la prueba con el BOM se ejecutó por primera vez contra modelos de verdad y dejó tres lecciones, cada una con su arreglo. Primera: **elegir el modelo por precio es mala idea**. La versión inicial cogía el primer modelo del catálogo que admitiera salida estructurada, le tocó uno diminuto, y mapeó una columna de siete diciendo que `Designator`, `Description` y `Quantity` no existían, con confianza `0.99`. El JSON era válido, así que ninguna validación de esquema lo habría detectado. Ahora, sin `-Modelo` se usa el del servicio, y `-Comparar` mide tres escalones de precio con un tope de gasto por llamada. Segunda: **un fallo mudo no sirve de nada**; el script imprimía `ERROR - :` porque leía el cuerpo del error de un stream que Windows PowerShell ya había consumido, y ahora sale el código HTTP, el del servicio, el mensaje y lo que dijo OpenRouter. Tercera: **un campo de texto sin límite es una invitación**; un modelo metió cinco mil tokens de deliberación dentro del campo que debía llevar el nombre de una columna, así que la petición lleva `max_tokens` y el esquema `maxLength`, y la estimación de coste se calcula con el prompt real en vez de con un número fijo.

## La decisión que deja tomada esta sesión

Comparando tres modelos sobre el mismo BOM de 105 componentes:

| Modelo | Campos | Tardó | Coste |
|---|---|---|---|
| `google/gemini-2.5-flash-lite` | 6/7 | 0,7 s | 0,000138 $ |
| `moonshotai/kimi-k2.5` | 6/7 aparente | 25,6 s | 0,019633 $ |
| `anthropic/claude-fable-5` | 0/7 | 8,5 s | 0,031780 $ |

El modelo de la casa acierta igual, tarda treinta y cinco veces menos y cuesta
ciento cuarenta veces menos. El séptimo campo, el precio unitario, no está en el
fichero, así que acertar es decir que falta. **Para leer listas de materiales,
pagar más no compra precisión**, y ese era el dato que hacía falta antes de
construir la aplicación de presupuestos.

El razonamiento del modelo caro, eso sí, aporta algo que guardar: `Comment` unas
veces trae el código del fabricante y otras una descripción, y `Referencia
principal` mezcla código de fabricante con código de distribuidor. Eso importará
al cruzar con tarifas.
